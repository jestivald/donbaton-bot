# ДонБатон: Wi-Fi и отдельные пакеты LTE

Кандидат форка на Bedolaga **v4.7.1**, upstream commit
`cd903b7cfd3bac6e08e571904662c88e8c151d1d`. Совместимый кабинет основан на
**v1.71.1**, commit `5ade78f506fd0e102d70e2d59af4aa97ef9c164b`.
Upstream LICENSE и история сохранены. В код перенесены действующие исправления:
email покупателя в чеке, LegalConsent в резервной копии, переключатель
административных уведомлений о нодах.

Цены за 30 суток утверждены владельцем 09.09.2026, продажи новых тарифов
включены вечером 09.09.2026 (тарифы `7/8/9/10`, старые `4/5/6` неактивны).

пусты: привязка к `DonBaton WIFI` / `DonBaton LTE` выполняется оператором).

Длинный период покупает только срок подписки: пакет LTE остаётся
60/120 ГиБ **каждые 30 суток** и обновляется циклом, а не выдаётся
целиком за весь срок. Продление любым периодом цикл LTE не сбрасывает.
Докупки LTE: 20/60/120 ГиБ за 79/199/349 ₽, срок 30 суток.
Себестоимость провайдеров неизвестна. При полном использовании включённого LTE
доплата 100/150 ₽ покрывает лишь 1,67/1,25 ₽/ГиБ до комиссий и прибыли.

Wi-Fi/LTE — названия групп серверов. Учёт не определяет тип сети телефона:
использование обходного сервера по Wi-Fi тоже расходует LTE-пакет.
1 ГиБ = 1 073 741 824 байта; считается upload + download, без коэффициента ×17.

## Правила

- Один пользователь панели и одна ссылка. Общий лимит панели равен нулю.
  При исчерпании LTE снимается только доступ к LTE-сквадам.
- Условия включённой квоты сохраняются на подписке. Изменение тарифной записи
  администратором не переписывает уже оплаченный лимит.
- Период — ровно 30 суток с первой активации. Досрочное продление сохраняет
  период и расход. Сброс текущего счётчика панели не выдаёт новый пакет.
- Докупка действует 30 суток с покупки, переживает обновление базового пакета
  и расходуется по ближайшей дате истечения. Она не продлевает подписку и
  не возобновляет административно отключённый или просроченный доступ.
- Мгновенная смена действующего тарифа с доплатой для новых категорий закрыта.
  При `DONBATON_TARIFF_SWITCH_ENABLED` другой тариф покупается в любой момент
  как обычная покупка на полный срок по обычной цене: оставшиеся дни текущего
  тарифа сохраняются и добавляются к новому сроку, доплаты и возврата разницы
  нет. Условия нового тарифа действуют сразу — объём LTE ложится на текущий
  цикл, не обнуляя расход, а лимит устройств меняется немедленно. В окне
  прежних оплаченных условий устройства меняются сразу, а новый объём LTE
  начинается после окончания этих условий. Индивидуальные условия
  (`renewal_requires_expiry`) и переход между старым и новым учётом
  по-прежнему ждут окончания оплаченного срока и явной миграции. Устройства
  сбрасываются только при уменьшении лимита. Выключенный флаг оставляет прежний
  запрет. Новая платная активация после окончания начинает новый период и
  сохраняет неистёкшие докупки.
- Новый пробный пакет выдаётся один раз в физических байтах: прежний лимит
  делится на 17 с округлением общего остатка вверх. Неиспользованный pending
  trial начинает сохранённую длительность при фактической оплате. Конвертация
  trial → paid выдаёт новый пакет после сверки последнего счётчика.
- Подарочные, суточные, произвольные тарифы и новые подключения внешнего
  рекуррентного платежа для этих категорий не входят в текущий кандидат.
  Покупка и продление с баланса поддерживаются.
- Старые тарифы имеют `network_category=NULL`. Автоматического переноса старых
  платных подписок в новый учёт нет: нужны сохранённые остатки, докупки и сроки.

## Включение на проверенном стенде

Миграция Alembic `0119` добавляет nullable поля категории и отдельные таблицы
`lte_quotas` / `lte_topups`. Аддитивная `0120` добавляет снимок старых прав,
pending/trial-состояние и независимую таблицу конечных panel-only прав.
Обе миграции сохраняют прежние строки; перенос выполняется явным оператором.

```dotenv
DONBATON_LTE_ENABLED=false
DONBATON_LTE_ACCOUNTING_READY=false
DONBATON_LTE_ACCOUNTING_EPOCH=
DONBATON_LTE_NODE_UUIDS=
DONBATON_WIFI_SQUAD_UUIDS=
DONBATON_LTE_SQUAD_UUIDS=
DONBATON_LTE_POLL_SECONDS=30
DONBATON_LTE_MAX_SAMPLE_AGE_SECONDS=180
DONBATON_LTE_TELEMETRY_GRACE_SECONDS=0
```

Оба списка — UUID через запятую. Нужны непересекающиеся сквады **и inbound**.
`allowed_squads` каждого нового тарифа должен точно совпадать с WIFI либо
WIFI + LTE. Внешние сквады для этой политики запрещены.
`ACCOUNTING_READY` — явное подтверждение оператора после проверки WIFI=0/LTE=1
и согласованного переноса всех затронутых старых аккаунтов; это не автоматический
анализ нод. Менять общий множитель 17→1, оставив старые лимиты, нельзя.

`ACCOUNTING_EPOCH` должен совпадать с эпохой окончательного снимка переноса.
`NODE_UUIDS` — UUID двух нод, отдельно от UUID сквадов. Независимый canary
подтверждает весь путь «реальный LTE-запрос → сохранённый счётчик панели» и
пишет ограниченный по возрасту Redis heartbeat. Без свежего доказательства
LTE закрыт даже при успешном GET пользователя. Подготовка описана в
[`scripts/donbaton/README.lte-telemetry.md`](../scripts/donbaton/README.lte-telemetry.md).

`TELEMETRY_GRACE_SECONDS` смягчает главный побочный эффект этой строгости:
canary снимает lease при отказе ЛЮБОГО из двух маршрутов, поэтому флап одного
плеча закрывал LTE всему флоту на минуты, хотя учёт не ломался. При
положительном значении консьюмер помнит последнее валидное доказательство в
Redis (`donbaton:lte:telemetry:<epoch>:last-valid`, TTL = grace +
`MAX_SAMPLE_AGE_SECONDS`) и столько секунд считает учёт подтверждённым, записывая
warning `LTE telemetry missing, within grace`. Плата прямая: при настоящей
поломке учёта LTE остаётся открытым до N секунд без подтверждения списаний.
`0` — прежнее строгое поведение; недоступный Redis тоже даёт строгое.

## Сохранение прежних оплаченных прав

Перенос хранит точные исходные целочисленные limit/used/lifetime, исходный
оплаченный конец и календарь Remnawave. Lifetime не пересчитывается задним
числом. Остаток старого общего пула равен `ceil(max(limit-used, 0)/17)`;
последующие физические дельты расходуют сохранённый числитель. Активация
требует неизменных panel ID и snapshot lifetime после завершения старых
начислений. Другой снимок/эпоха не заменяет уже импортированный ledger.

Старый календарь и фактический лимит устройств панели действуют до первоначального оплаченного
конца. Раннее продление не передвигает эту границу. Индивидуальные условия
нельзя продлить раньше неё; это проверяется до списания баланса. Старые
TrafficPurchase остаются как финансовая история, а общий оплаченный хвост
ведёт ledger, включая срок после окончания старой базы. Новый Wi-Fi-тариф
может использовать ранее оплаченный LTE-хвост без нового базового LTE.
Если panel HWID limit равен `null`, прежний безлимит устройств сохраняется как
`0`; исходное отличающееся значение бота остаётся внутри аудиторского снимка.

Фоновое автопродление индивидуальные условия не оплачивает. Запрет снимается не
по дате, а явной покупкой клиента: до окончания срока действуют прежние условия,
после — тариф выбирает сам клиент, а технический target импорта согласием на
оплату не является. Отметка покупки (`runtime.purchased_at`) ставится в
`update_entitlement` и не зависит от объёма LTE: тариф «Только Wi-Fi» даёт
нулевой пакет, и признак по значению потерял бы состоявшуюся покупку.
Продление одних лишь дней (`extend_subscription` без `tariff_id`: промокод на
дни, реферальная награда, кампания, админское «+N дней») отметку не ставит само
по себе, но и обойти политику не может: пока окно совместимости открыто,
`_prepare_donbaton_subscription` вызывает `validate_legacy_renewal` и продление
управляемой подписки отклоняется целиком, а когда окно закрылось, срок уже
истёк — ветка `expired` уводит в `update_entitlement`, и отметка ставится
(бесплатные дни там засчитываются как решение клиента).

Известная граница — прямая запись `subscription.end_date` мимо
`extend_subscription` (админская установка даты, `admin_users.py`): она обходит
и guard, и `update_entitlement`, и подписка остаётся живой уже за
`original_paid_until`. После этого даже оплаченное клиентом продление того же
тарифа идёт в `initialize_quota` без отметки: платёж проходит, а автопродление
остаётся выключенным и бот просит выбрать тариф. Различить оплату и бонусные
дни на этом пути сейчас нечем — все точки вызова `extend_subscription` передают
одинаковые аргументы, признак платности пришлось бы заводить сразу в 18 файлах;
отдельная задача. Рабочий выход для такого клиента — выбрать тариф явно, через
путь `update_entitlement`. `legacy_state` при этом нигде не обнуляется, поэтому
отметка и снимок переживают любые правки срока. Пропуск — штатное событие
уровня `info`
с одноразовым (на 7 суток) объяснением клиенту, а не ошибка списания;
уведомление об истечении такой подписке автопродление не обещает — ни при
включённом автоплатеже, ни при выключенном. Рекуррентное пополнение с карты
проверяет тот же предикат до расчёта цены, чтобы не списать «под продление»,
которого не будет. Докупка LTE остаётся доступна.

Старые checkout-ссылки и сохранённые корзины после включения новой сетки
не активируют устаревшие условия. Уже принятый платёж остаётся на балансе.
Количество устройств новой сетки фиксировано тарифом; старые кнопки докупки
и уменьшения устройств отклоняются на сервере.

До первого корректного lifetime-замера доступен Wi-Fi. Регресс счётчика,
другая личность panel-user или устаревший замер закрывают LTE до сверки.
Фоновый опрос следует запуску/остановке MonitoringService.
Сбор трафика, опрос и применение прав асинхронны: отключение не происходит
на последнем байте. При недоступности панели конечный перерасход не гарантируется.
Расход вокруг границы периода относится к предыдущему периоду первым успешным
замером; точность границы ограничена интервалом наблюдения.

## Уведомления об остатке LTE

Бот присылает клиенту два уведомления: «📶 LTE почти закончился» — остаток пакета
не больше `DONBATON_LTE_LOW_NOTICE_GB` ГиБ, но ещё больше нуля, и «📵 LTE
закончился». Под текстом — «📶 Докупить LTE» и «📱 Моя подписка». Кнопка и строка
«Докупить LTE можно кнопкой ниже» появляются, только если докупка этой подписке
действительно доступна (условия `purchase_lte_topup`): действующая платная
подписка «Wi-Fi + LTE», у тарифа включена докупка и есть пакеты, лимит активных
докупок не исчерпан, у пользователя нет запрета покупок. В мультитарифе кнопки
ведут к этой подписке (`st:{id}` / `sm:{id}`, в кабинете `/subscriptions/{id}`),
иначе на общие `buy_traffic` / `menu_subscription`. Остаток пишется в ГиБ, дата
окончания подписки — как на экране LTE (`%d.%m.%Y %H:%M` и пояс `TIMEZONE`).

Решение принимает цикл учёта: `reconcile_subscription` после `apply_panel_policy`,
на строке `lte_quotas` под `FOR UPDATE` и в той же транзакции, что и замер.
Отметки `low_notice_sent_at` / `exhausted_notice_sent_at` (миграция `0127`, те же
колонки в `lte_orphan_quotas`) ставятся **до** отправки, поэтому каждое сообщение
уходит не больше одного раза: сбой доставки теряет сообщение, но не повторяет его.
Снимаются отметки по леджеру: остаток выше порога снимает обе (докупка, новый
период, ручная добавка), любой положительный остаток снимает «закончился» —
маленькая добавка ниже порога заново взводит только его. Если за один проход
остаток упал сразу в ноль, уходит одно «закончился», а «почти» отмечается по пути.

Ничего не отправляется, если учёт не `ready` (`stale`, `pending`, `regressed` и
т. д.) или нет живой аренды канарейки — в том числе в grace-окне
`DONBATON_LTE_TELEMETRY_GRACE_SECONDS`, когда LTE открыт, а учёт не подтверждён.
Не пишем также истёкшей или неактивной подписке, заблокированному пользователю,
клиенту без доступа вовсе (панель `DISABLED`/`EXPIRED`), безлимитному legacy и
подписке с нулевой ёмкостью LTE: у «Только Wi-Fi» пакет нулевой, в леджере она
всегда `exhausted`. Legacy-пул считается в настоящих байтах (/17). Пробные по
умолчанию пропускаются: их пакет (~0,59 ГиБ) ниже порога с первой минуты.
Клиент отписывается переключателем «Предупреждения о трафике» в кабинете
(`traffic_warning_enabled`); общий `ENABLE_NOTIFICATIONS` тоже действует.

`run_quota_cycle` в Telegram не пишет, а возвращает кандидатов;
`MonitoringService._lte_loop` передаёт их в `lte_quota_notifications.dispatch`
фоновой задачей, чтобы медленный Telegram не задерживал следующий проход,
который снимает LTE. `dispatch` не бросает исключений и пишет итог в лог
`LTE notices dispatched` (`sent`, `not_delivered`, `failed`, `missing`, `skipped`).
Предохранитель: если за один проход набралось больше
`DONBATON_LTE_NOTICE_MAX_PER_CYCLE` кандидатов, клиентам не пишем никому,
отметки остаются, а в чат админов (категория «Инфраструктура») не чаще раза в час
приходит «N кандидатов больше лимита, отправка пропущена». Так первый проход
после выкладки не рассылает сообщения всем, у кого LTE уже мало: им в текущем
периоде ничего не придёт.

Права только в панели (`lte_orphan_quotas`) написать некому. При
`DONBATON_LTE_NOTICE_ADMIN_ORPHANS=true` о них сообщается в чат админов: ID и
username в панели, остаток, событие. По решению владельца от 25.09.2026 флаг
выключен: сирот и только-панельных пользователей он разбирает вручную.
Только-панельные пользователи без строки в `lte_orphan_quotas` в учёт бота не
входят, уведомлений у них нет. Клиенты без Telegram (только email) получают
лишь событие кабинета по WebSocket, которое кабинет не показывает: email-шаблона
для этих типов пока нет.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `DONBATON_LTE_NOTICE_ENABLED` | `true` | главный выключатель обоих уведомлений |
| `DONBATON_LTE_LOW_NOTICE_GB` | `1.0` | порог «почти закончился», ГиБ; `0` выключает это уведомление |
| `DONBATON_LTE_EXHAUSTED_NOTICE_ENABLED` | `true` | «LTE закончился» |
| `DONBATON_LTE_NOTICE_TRIALS` | `false` | писать ли пробным подпискам |
| `DONBATON_LTE_NOTICE_ADMIN_ORPHANS` | `false` | сообщать админам о правах только в панели |
| `DONBATON_LTE_NOTICE_MAX_PER_CYCLE` | `20` | предохранитель от залпа за один проход |
| `DONBATON_LTE_LOW_NOTICE_TEXT` | пусто | свой текст «почти закончился»; пусто — локаль |
| `DONBATON_LTE_EXHAUSTED_NOTICE_TEXT` | пусто | свой текст «закончился»; пусто — локаль |

Ключи правятся в админке бота («⚙️ Настройки» → «🧩 Конфигурация бота» →
«📦 Прочие настройки» → «Donbaton») или в разделе настроек кабинета и
применяются сразу. В `.env` их не задавать: значение из окружения молча
блокирует правку из админки, поэтому в `.env.example` они закомментированы.

### Где владельцу править тексты

1. **Админка бота, без выкладки.** `DONBATON_LTE_LOW_NOTICE_TEXT` и
   `DONBATON_LTE_EXHAUSTED_NOTICE_TEXT` принимают текст в несколько строк с
   разметкой HTML Telegram (`<b>`, `<i>`, `<u>`, `<a href="…">`), теги набираются
   прямо текстом. Подстановки: `{tariff}` — тариф, `{remaining}` — остаток в ГиБ,
   `{end_date}` — окончание подписки. Строку о докупке и кнопки бот добавит сам.
   Текст один для всех языков интерфейса. После сохранения карточка настройки
   показывает текст уже с разметкой. Если карточка не открылась, в HTML ошибка,
   и Telegram не примет такое сообщение. Ошибка в фигурных скобках не страшна:
   уйдёт текст из локали, в логе будет предупреждение. Вернуть текст локали
   можно кнопкой «♻️ Сбросить» на карточке настройки. В кабинете поле становится
   многострочным, когда значение длиннее 50 символов, поэтому первую версию
   удобнее вводить через бота.
2. **Локали.** Ключи `LTE_QUOTA_LOW_NOTICE`, `LTE_QUOTA_EXHAUSTED_NOTICE`,
   `LTE_QUOTA_NOTICE_TOPUP_HINT` и `LTE_QUOTA_NOTICE_TOPUP_BUTTON` лежат
   в `app/localization/locales/{ru,en,ua,fa,zh}.json`; кнопка «Моя подписка» —
   общий ключ `MY_SUBSCRIPTION_BUTTON`. На сервере без пересборки образа
   используйте файл `ru.json` (или другого языка) в каталоге `LOCALES_PATH`
   (в docker-compose — `./locales` → `/app/locales`) с нужными ключами. Он
   накладывается поверх встроенных текстов (`app/localization/loader.py`),
   а применяется после перезапуска бота: локали кэшируются.
